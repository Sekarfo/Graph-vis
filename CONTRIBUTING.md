# Как работать над графами нескольким людям параллельно

Каждая область — **отдельный файл** `regions/<slug>.json` (+ `regions/<slug>.fallback.js`,
генерируется автоматически). Сервер сам находит все области сканированием
папки `regions/` (`discover_graphs()` в `server.py`) — **общего списка/реестра
в коде нет**. Из этого следует главное свойство структуры:

> Двое человек, работающих каждый над своей областью, никогда не конфликтуют
> в git — они трогают разные файлы. Не нужно ничего согласовывать заранее,
> не нужно по очереди мержить один и тот же список регионов.

Единственное, что теоретически может пересечься — если два человека независимо
возьмут один и тот же `slug` или один и тот же `idPrefix` (буква для id новых
узлов). `scripts/new_region.py` подбирает свободный префикс автоматически,
`scripts/validate_region.py` проверяет отсутствие коллизии перед коммитом —
если коллизия всё же случится (два PR одновременно), её увидят на этапе
ревью/CI, а не в проде.

## Быстрый старт: беру область N

```bash
git clone <URL этого репозитория> graph-vis
cd graph-vis
git checkout -b region/akmola          # своя ветка на свою область
pip install -r requirements.txt

# область ещё не существует — создаём скелет:
python scripts/new_region.py akmola "Акмолинская область"
# → regions/akmola.json (пустой, с рамкой meta) + regions/akmola.fallback.js

uvicorn server:app --reload
# → http://localhost:8000
```

Открываем `http://localhost:8000/index.html?graph=akmola&edit=1` — сразу в
режиме правки (`edit=1`). Дальше два пути наполнить область данными:

1. **Руками через интерфейс** — кнопки «➕ Объект» / «🔗 Связь» / перетаскивание.
   Годится для маленьких правок и точечного добавления объектов.
2. **Скриптом-оцифровщиком** (как `almaty-zhetysu` был собран из PDF) — пишете
   свой Python-скрипт, который кладёт готовый JSON прямо в `regions/akmola.json`
   в том же формате (см. существующие файлы как образец структуры), затем
   `python scripts/build_fallback.py regions/akmola.json` для fallback-файла.
   Сервер подхватит новый файл при следующем запуске (или сразу, если он же
   его и писал через `/api/graph/*`).

Оба пути ведут к одному и тому же: файлу `regions/<slug>.json`, который потом
коммитится.

## Правлю уже существующую область (например, нашёл ошибку в Жамбылской)

```bash
git checkout -b fix/zhambyl-typo
uvicorn server:app --reload
```

Открываем `http://localhost:8000/index.html?graph=zhambyl&edit=1`, находим
объект (поиск в шапке — понимает опечатки и каз/рус разночтения), кликаем,
правим название/км/позицию в панели справа, «💾 Сохранить». Правка сразу же
лежит в `regions/zhambyl.json` на диске — сервер их пишет напрямую, ничего
руками собирать не надо.

Если нужно завести новый объект или связь — «➕ Объект» / «🔗 Связь» в шапке
(подробности — README.md, раздел «Редактирование графа с фронта»).

## Перед тем как пушить

```bash
python scripts/validate_region.py regions/akmola.json
```

Проверяет: JSON не битый, `meta.registry` заполнен и slug совпадает с именем
файла, все `kind`/`subtype`/`type` — из допустимого набора, все `from`/`to`
рёбер ссылаются на существующие узлы, id не дублируются, `idPrefix` не занят
другой областью и не совпадает со служебными буквами (`E` — id рёбер, `X` —
псевдоузлы внешних связей), а также что ни один **id узла** не встречается в
файле соседней области. Без аргумента проверяет **все** `regions/*.json`
разом — полезно перед PR, чтобы случайно не задеть соседей.

Если ругается на занятый `idPrefix` или на пересечение id узлов — сменить
одну строку `meta.registry.idPrefix` НЕДОСТАТОЧНО: id уже созданных узлов
останутся со старой буквой, и `server.py` продолжит молча пропускать область
целиком (`discover_graphs()` считает совпадение префиксов фатальным — при нём
привязка отчёта от бота могла бы указать на узел чужого графа). Чинит скрипт,
который переписывает букву во всех ссылках файла сразу:

```bash
python scripts/repair_id_prefix.py kyzylorda Q --dry-run   # посмотреть
python scripts/repair_id_prefix.py kyzylorda Q --rebuild-fallback
```

Без второго аргумента берётся первая свободная буква.

Если правили несколько файлов — коммитьте **только свои**:

```bash
git add regions/akmola.json regions/akmola.fallback.js
git commit -m "Акмолинская область: скелет + первые районы"
git push -u origin region/akmola
```

Открываете PR. Ревьюер (или CI, если настроите — `validate_region.py` возвращает
код 1 при ошибках, годится для любого CI) прогоняет `validate_region.py`,
смотрит diff (он у вас будет только по своим файлам) и мержит.

## Деплой

`Dockerfile` копирует папки `regions/` и `smr/` целиком — добавление новой
области **не требует правки Dockerfile**. Но обе папки едут в образ ровно тем,
что лежит в git: файл, оставшийся неотслеженным (`??` в `git status`), до
продакшена не доедет, и область просто не появится в селекторе.

Если по вашей области есть строки в своде СМР (книга «Отчет СОИ»), после
оцифровки прогоните `python scripts/import_smr.py` — он пересоберёт `smr/*.json`
и отчёт о сверке `SMR_RECONCILE.md`, где будет видно, какие сёла свода не нашли
узла в вашем графе. После мержа в
основную ветку и деплоя на Railway новая область появится в селекторе
автоматически (см. `GET /api/graphs` во фронте).

Если Railway настроен с persistent volume (`DATA_DIR`) — при первом запуске
после деплоя новые файлы из `regions/` докопируются в volume сами
(`discover_graphs()` сидирует недостающее), существующие в volume не
перезаписываются (правки, сделанные через живой вьюер, не теряются).

## Конвенции формата (коротко)

- `id` узла — `<idPrefix><hex>`, генерируется сервером сам при добавлении
  через UI; при ручном/скриптовом наполнении — любой уникальный в пределах
  файла, начинающийся с вашего `idPrefix` (так привязка `graph_from_node`/
  `graph_to_node` от бота никогда не перепутает область).
- `district` — человекочитаемое название района как на чертеже («Байзакский
  район»); используется для нечёткого сопоставления с БД бота, не обязано
  быть машинно-нормализованным.
- `x`/`y` — координаты раскладки в условных единицах редактора (не гео-
  координаты); если оцифровываете с PDF/чертежа — берите координаты прямо
  оттуда (в pt), маштаб не важен, вьюер сам вписывает всё в экран («⤢ Вписать»).
- Полная схема полей — `meta.schema` внутри самого JSON и README.md.

## Локальный вьюер без сервера (только просмотр)

Если Python поднимать не хочется, а нужно быстро посмотреть область:
двойной клик по `index.html` — откроется `file://`, данные подтянутся из
`regions/<slug>.fallback.js`. Правка в этом режиме недоступна (кнопка
«✏️ Правка» покажет «нет связи с server.py») — для правок нужен запущенный
`uvicorn` (см. выше).
